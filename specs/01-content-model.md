# 01. コンテンツモデル（配布フォルダ・README フロントマター）

## 1. 配布フォルダ構造

```text
catalog/
├── <slug>/
│   ├── README.md            # 必須。フロントマター + 本文
│   ├── *.agent.md           # 種別に応じた配布ファイル
│   ├── *.prompt.md
│   ├── SKILL.md
│   └── <任意のサブフォルダ>/   # 参照資料など
└── <slug>/
    └── ...
```

- `catalog/` 直下のフォルダ 1 つが 1 アイテムに対応する。
- 配布フォルダ内のファイルはすべてダウンロード対象となる（[05-download-command.md](./05-download-command.md)）。

## 2. フロントマタースキーマ

| キー | 必須 | 型 | 制約 | 用途 |
|---|---|---|---|---|
| `title` | 必須 | string | 前後空白除去後 1〜80 文字 | 一覧・詳細の見出し |
| `summary` | 必須 | string | 前後空白除去後 1〜200 文字、改行を含まない | 一覧の概要、検索対象 |
| `tags` | 必須 | string[] | 1〜10 要素。各要素は 1〜30 文字で空白・カンマを含まない。正規化後に重複しない | 検索・絞り込み |
| `type` | 必須 | enum | `agent` / `skill` / `prompt` / `bundle` | 種別絞り込み・表示 |
| `version` | 任意 | string | SemVer 2.0.0 形式（例: `1.2.0`） | 詳細ページのメタ情報 |
| `author` | 任意 | string | 1〜50 文字 | 詳細ページのメタ情報 |
| `updated` | 任意 | date | `YYYY-MM-DD` 形式の実在する日付 | 詳細ページのメタ情報、並び順 |

### 記述例

```markdown
---
title: TDD オーケストレーション
summary: 詳細設計書からテストファーストで C# 実装を自動化するエージェント群
tags: [tdd, csharp, orchestration]
type: bundle
version: 1.0.0
updated: 2026-10-04
---

# TDD オーケストレーション

本文（使い方など）...
```

## 3. 要件

### CNT-001 配布フォルダの配置

- パターン: ユビキタス
- EARS: 各アイテムは `catalog/<slug>/` フォルダとして配置されなければならない。
- 事前条件: なし
- 事後条件: アイテム数 = `catalog/` 直下のフォルダ数
- 不変条件: `catalog/` 直下にファイルを置かない（`catalog/` 直下の `README.md` を除く）
- 検証: ビルド検証

### CNT-002 slug の命名規則

- パターン: ユビキタス
- EARS: slug は正規表現 `^[a-z0-9]+(-[a-z0-9]+)*$` に一致し、1〜64 文字でなければならない。
- 事前条件: なし
- 事後条件: slug はそのまま URL パスと giget のパスに使用できる
- 不変条件: slug は全アイテムで一意である（フォルダ名であるため構造的に保証される）
- 検証: 単体テスト（`validateSlug`）、ビルド検証

### CNT-003 README の必須化

- パターン: ユビキタス
- EARS: 各配布フォルダは、直下に `README.md`（大文字・小文字を区別）を 1 つ含まなければならない。
- 事前条件: 配布フォルダが存在する
- 事後条件: アイテムごとにフロントマターと本文が取得できる
- 不変条件: なし
- 検証: ビルド検証

### CNT-004 フロントマターの必須項目

- パターン: ユビキタス
- EARS: アイテム README は、先頭行から始まる YAML フロントマターに `title`・`summary`・`tags`・`type` を含まなければならない。
- 事前条件: `README.md` が存在する
- 事後条件: 必須 4 項目が「2. フロントマタースキーマ」の制約を満たす
- 不変条件: なし
- 検証: 単体テスト（`itemSchema`）、ビルド検証

### CNT-005 未定義キーの禁止

- パターン: 望ましくない振る舞い
- EARS: もしフロントマターにスキーマ未定義のキーが含まれるならば、ビルドは当該キー名と slug を示して失敗しなければならない。
- 事前条件: フロントマターが YAML として解析できる
- 事後条件: 公開されるアイテムのフロントマターは定義済みキーのみからなる
- 不変条件: なし
- 検証: 単体テスト、ビルド検証
- 備考: 誤記（例: `tag`）を早期に検出するため

### CNT-006 タグの正規化

- パターン: ユビキタス
- EARS: サイトは、タグを比較・表示する際に NFKC 正規化と小文字化を適用した値を用いなければならない。
- 事前条件: タグが CNT-004 の制約を満たす
- 事後条件: `TDD` と `tdd`、全角 `ＴＤＤ` は同一タグとして扱われる
- 不変条件: README 上の元の表記は変更しない
- 検証: 単体テスト（`normalizeTag`）

### CNT-007 タグの重複禁止

- パターン: 望ましくない振る舞い
- EARS: もし 1 つのアイテムの `tags` に正規化後に同一となる要素が複数含まれるならば、ビルドは当該 slug と重複タグを示して失敗しなければならない。
- 事前条件: タグが文字列配列として解析できる
- 事後条件: 各アイテムのタグ集合は正規化後に重複がない
- 不変条件: なし
- 検証: 単体テスト、ビルド検証

### CNT-008 種別ごとの必須ファイル

- パターン: ユビキタス
- EARS: 配布フォルダは、`type` に応じて次のファイルを直下に含まなければならない。
  - `agent`: `*.agent.md` を 1 つ以上
  - `prompt`: `*.prompt.md` を 1 つ以上
  - `skill`: `SKILL.md` を 1 つ
  - `bundle`: `README.md` 以外のファイルを 1 つ以上（サブフォルダ内を含む）
- 事前条件: `type` が有効な値である
- 事後条件: ダウンロードしたフォルダが種別に応じた利用可能なファイルを含む
- 不変条件: なし
- 検証: ビルド検証

### CNT-009 本文の任意性

- パターン: ユビキタス
- EARS: アイテム README の本文は空であってもよい。
- 事前条件: フロントマターが CNT-004 を満たす
- 事後条件: 本文が空の場合、詳細ページは本文領域に「説明はありません」と表示する（[04-detail-page.md](./04-detail-page.md) の DTL-004）
- 不変条件: なし
- 検証: E2E テスト

### CNT-010 skill 名と slug の一致

- パターン: オプション
- EARS: `type` が `skill` の場合、配布フォルダ直下の `SKILL.md` のフロントマター `name` は slug と一致しなければならない。
- 事前条件: CNT-008 により `SKILL.md` が存在する
- 事後条件: `./<slug>` に取得したフォルダをそのまま Skills フォルダへ置くと、フォルダ名と skill 名が一致する
- 不変条件: なし
- 検証: ビルド検証
- 備考: Agent Skills の仕様では skill 名と親フォルダ名の一致が求められるため

## 4. モジュール契約

### `itemSchema`（Astro Content Collections のスキーマ）

| 項目 | 内容 |
|---|---|
| シグネチャ | `itemSchema.parse(frontmatter: unknown): ItemFrontmatter` |
| 事前条件 | `frontmatter` は YAML 解析済みのオブジェクトである |
| 事後条件 | 戻り値は「2. フロントマタースキーマ」の全制約を満たす。`title`/`summary` は前後空白除去済み |
| 不変条件 | 入力オブジェクトを変更しない |
| 違反時 | どのキーがどの制約に違反したかを含むエラーを送出する |

### `validateSlug`

| 項目 | 内容 |
|---|---|
| シグネチャ | `validateSlug(slug: string): boolean` |
| 事前条件 | `slug` は文字列である |
| 事後条件 | CNT-002 の正規表現と長さ制約を満たす場合に限り `true` を返す |
| 不変条件 | 副作用なし |
| 違反時 | 文字列以外が渡された場合は `TypeError` を送出する |

### `normalizeTag`

| 項目 | 内容 |
|---|---|
| シグネチャ | `normalizeTag(tag: string): string` |
| 事前条件 | `tag` は 1 文字以上の文字列である |
| 事後条件 | 戻り値 = `tag.normalize("NFKC").toLowerCase()`。冪等（`normalizeTag(normalizeTag(x)) === normalizeTag(x)`） |
| 不変条件 | 副作用なし |
| 違反時 | 空文字列の場合は `RangeError` を送出する |
