# 06. デプロイ（GitHub Actions / GitHub Pages）

## 1. 構成

| ワークフロー | ファイル | 目的 |
|---|---|---|
| デプロイ | `.github/workflows/deploy-pages.yml` | `main` の内容をビルドし GitHub Pages へ公開する |
| 検証 | `.github/workflows/validate.yml` | PR 上でカタログ検証・テスト・ビルドを行う（公開しない） |

- リポジトリ設定の **Settings > Pages > Source** は「GitHub Actions」とする。
- 公開 URL は `https://aco-lone.github.io/CopilotPrompts/`（BLD-010 の `site` + `base`）。

## 2. 要件

### DEP-001 デプロイのトリガー

- パターン: イベント駆動
- EARS: `main` ブランチへ `catalog/**`・`site/**`・`.github/workflows/deploy-pages.yml` のいずれかを変更するコミットが push されたとき、デプロイワークフローはサイトをビルドし GitHub Pages へ公開しなければならない。
- 事前条件: リポジトリの Pages ソースが「GitHub Actions」に設定されている
- 事後条件: 公開サイトは当該コミットの `catalog/` の内容を反映する
- 不変条件: 上記以外のパスのみの変更ではデプロイしない
- 検証: ワークフロー実行ログの確認

### DEP-002 手動デプロイ

- パターン: イベント駆動
- EARS: 保守者が `workflow_dispatch` でデプロイワークフローを起動したとき、デプロイワークフローは `main` の最新コミットでビルド・公開しなければならない。
- 事前条件: 起動者がリポジトリへの書き込み権限を持つ
- 事後条件: DEP-001 と同じ
- 不変条件: なし
- 検証: ワークフロー実行ログの確認

### DEP-003 ビルド手順

- パターン: ユビキタス
- EARS: デプロイワークフローは、`site/` で `npm ci`・`npm run validate`・`npm test`・`npm run build` をこの順に実行し、`site/dist/` を Pages 成果物としてアップロードしなければならない。
- 事前条件: `site/package-lock.json` が存在する。Node.js のバージョンは `site/.nvmrc` で指定された LTS である
- 事後条件: 成果物は `actions/upload-pages-artifact` でアップロードされ、`actions/deploy-pages` で公開される
- 不変条件: いずれかの手順が失敗した場合、後続の手順を実行しない
- 検証: ワークフロー実行ログの確認

### DEP-004 失敗時の公開維持

- パターン: 望ましくない振る舞い
- EARS: もしデプロイワークフローのいずれかの手順が失敗したならば、デプロイワークフローは公開を行わず、ワークフローを失敗として終了しなければならない。
- 事前条件: なし
- 事後条件: 公開中のサイトは直前に成功したデプロイの内容のまま維持される
- 不変条件: 失敗したビルドの成果物は公開されない
- 検証: 不正なアイテムを含むブランチでの試行

### DEP-005 PR での事前検証

- パターン: イベント駆動
- EARS: `main` を対象とする PR で `catalog/**` または `site/**` が変更されたとき、検証ワークフローは DEP-003 の `npm run build` までを実行し、結果を PR のチェックとして報告しなければならない。
- 事前条件: なし
- 事後条件: カタログ違反（BLD-003）がある PR はチェックが失敗する
- 不変条件: 検証ワークフローは Pages へ公開しない
- 検証: PR 上のチェック結果の確認

### DEP-006 最小権限

- パターン: ユビキタス
- EARS: デプロイワークフローは、権限を `contents: read`・`pages: write`・`id-token: write` に限定しなければならない。検証ワークフローは `contents: read` のみに限定しなければならない。
- 事前条件: なし
- 事後条件: ワークフローはリポジトリへの書き込みを行わない
- 不変条件: なし
- 検証: ワークフロー定義のレビュー

### DEP-007 同時実行の制御

- パターン: 状態駆動
- EARS: あるデプロイが実行中の間、デプロイワークフローは後続のデプロイを `pages` 同時実行グループで待機させ、実行中のデプロイを取り消してはならない。
- 事前条件: なし
- 事後条件: 公開されるのは最後に完了したデプロイの内容である
- 不変条件: 2 つのデプロイが同時に公開処理を行わない
- 検証: ワークフロー定義のレビュー（`concurrency: { group: pages, cancel-in-progress: false }`）

### DEP-008 base パスの適用

- パターン: ユビキタス
- EARS: サイトは、すべての内部リンク・静的アセット参照に BLD-010 の `base` パスを付与しなければならない。
- 事前条件: なし
- 事後条件: `https://aco-lone.github.io/CopilotPrompts/` 配下で全ページ・アセットが 404 にならない
- 不変条件: ページ・コンポーネント内でルート相対パス（`/` 始まり）を直書きしない
- 検証: E2E テスト（ビルド成果物を base パス付きでプレビュー）、リンクチェック
