# 03. トップページ（一覧・検索・絞り込み）

## 1. 画面構成

| 領域 | 内容 |
|---|---|
| ヘッダー | サイト名、GitHub リポジトリへのリンク |
| 検索欄 | フリーワード入力欄（`<input type="search">`）、クリアボタン |
| 種別フィルター | 「すべて」「agent」「skill」「prompt」「bundle」の単一選択 |
| タグフィルター | 全タグの一覧（タグ名と件数）。複数選択可 |
| 件数表示 | 「N 件 / 全 M 件」 |
| アイテム一覧 | アイテムカードの並び |

### アイテムカード

| 要素 | 内容 |
|---|---|
| タイトル | `title`。詳細ページへのリンク |
| 概要 | `summary` |
| 種別バッジ | `type` |
| タグ | `tags`（README 上の表記で表示） |

- URL: `<base>/`（例: `https://aco-lone.github.io/CopilotPrompts/`）

## 2. 検索・絞り込み条件の定義

- **正規化**: 比較対象と入力の双方に `normalizeTag` と同じ処理（NFKC 正規化 + 小文字化）を適用する。
- **フリーワード**: 入力を前後空白除去後、空白（半角・全角）で分割した各語を「キーワード」とする。
  アイテムは、すべてのキーワードについて `title`・`summary`・`tags` のいずれかがそのキーワードを部分文字列として含むときに一致する（AND）。
- **種別**: 「すべて」以外が選択されている場合、`type` が一致するアイテムのみ一致する。
- **タグ**: 選択されたすべてのタグを持つアイテムのみ一致する（AND）。
- **組み合わせ**: フリーワード・種別・タグの各条件をすべて満たすアイテムを表示する（AND）。

## 3. 要件

### TOP-001 一覧表示

- パターン: ユビキタス
- EARS: トップページは、カタログ索引の全アイテムをアイテムカードとして索引順（BLD-013）に表示しなければならない。
- 事前条件: カタログ索引がページに埋め込まれている
- 事後条件: 絞り込み条件が無い状態で、表示カード数 = 索引のエントリ数
- 不変条件: カードの並び順は絞り込みによって変化しない（相対順序を保つ）
- 検証: E2E テスト

### TOP-002 詳細ページへの遷移

- パターン: イベント駆動
- EARS: 利用者がアイテムカードのタイトルまたはカード領域をクリックしたとき、トップページは当該アイテムの詳細ページ `<base>/items/<slug>/` へ遷移しなければならない。
- 事前条件: 当該アイテムが表示されている
- 事後条件: ブラウザの URL が詳細ページの URL になる
- 不変条件: 遷移はページ内リンク（`<a href>`）で行い、ブラウザの「戻る」でトップページに戻れる
- 検証: E2E テスト

### TOP-003 フリーワード検索

- パターン: イベント駆動
- EARS: 利用者が検索欄の内容を変更したとき、トップページは「2. 検索・絞り込み条件の定義」に一致するアイテムのみを表示しなければならない。
- 事前条件: クライアント側スクリプトが実行可能である
- 事後条件: 表示件数 ≦ 全件数。表示中の全アイテムが条件に一致し、非表示の全アイテムが条件に一致しない
- 不変条件: カタログ索引を変更しない
- 検証: 単体テスト（`filterItems`）、E2E テスト

### TOP-004 空のフリーワード

- パターン: 状態駆動
- EARS: 検索欄が空または空白のみである間、トップページはフリーワード条件を適用してはならない。
- 事前条件: なし
- 事後条件: 表示結果は種別・タグ条件のみで決まる
- 不変条件: なし
- 検証: 単体テスト

### TOP-005 種別絞り込み

- パターン: イベント駆動
- EARS: 利用者が種別フィルターを選択したとき、トップページは選択した種別のアイテムのみを表示しなければならない。「すべて」を選択したときは種別条件を解除しなければならない。
- 事前条件: クライアント側スクリプトが実行可能である
- 事後条件: 表示中の全アイテムの `type` が選択値に等しい（「すべて」を除く）
- 不変条件: 他の条件（フリーワード・タグ）の入力値を変更しない
- 検証: E2E テスト

### TOP-006 タグ絞り込み

- パターン: イベント駆動
- EARS: 利用者がタグフィルターのタグを選択または選択解除したとき、トップページは選択中のすべてのタグを持つアイテムのみを表示しなければならない。
- 事前条件: クライアント側スクリプトが実行可能である
- 事後条件: 表示中の全アイテムの `normalizedTags` が選択タグ集合を包含する
- 不変条件: 他の条件の入力値を変更しない
- 検証: E2E テスト

### TOP-007 カード上のタグからの絞り込み

- パターン: イベント駆動
- EARS: 利用者がアイテムカード上のタグをクリックしたとき、トップページは当該タグをタグフィルターの選択状態に追加しなければならない。
- 事前条件: 当該タグがまだ選択されていない
- 事後条件: TOP-006 の条件で再絞り込みされる
- 不変条件: 詳細ページへは遷移しない
- 検証: E2E テスト

### TOP-008 タグ一覧の構成

- パターン: ユビキタス
- EARS: タグフィルターは、全アイテムの正規化済みタグを重複なく、件数の降順、同数の場合は正規化済みタグ名の昇順で表示しなければならない。
- 事前条件: カタログ索引が存在する
- 事後条件: 各タグの件数 = そのタグを持つアイテム数
- 不変条件: 件数は絞り込み状態によって変化しない（全件基準）
- 検証: 単体テスト

### TOP-009 件数表示

- パターン: イベント駆動
- EARS: 表示アイテムが変化したとき、トップページは「表示件数 / 全件数」を更新しなければならない。
- 事前条件: なし
- 事後条件: 表示件数 = 表示中のカード数
- 不変条件: 全件数 = 索引のエントリ数
- 検証: E2E テスト

### TOP-010 一致なし

- パターン: 望ましくない振る舞い
- EARS: もし条件に一致するアイテムが 0 件ならば、トップページは「条件に一致するアイテムはありません」というメッセージと、すべての条件を解除するボタンを表示しなければならない。
- 事前条件: 少なくとも 1 つの条件が設定されている
- 事後条件: 解除ボタン押下後、検索欄は空、種別は「すべて」、タグ選択は空となり、全アイテムが表示される
- 不変条件: なし
- 検証: E2E テスト

### TOP-011 URL クエリとの同期

- パターン: イベント駆動
- EARS: 絞り込み条件が変化したとき、トップページは条件を URL クエリ `?q=<フリーワード>&type=<種別>&tags=<タグ1>,<タグ2>` に反映しなければならない。
- 事前条件: なし
- 事後条件: 条件が既定値（空・すべて・未選択）のパラメータは URL から除去される。履歴は `history.replaceState` で更新し、入力のたびに履歴を増やさない
- 不変条件: ページの再読み込みを発生させない
- 検証: E2E テスト

### TOP-012 URL クエリからの復元

- パターン: イベント駆動
- EARS: クエリ付き URL でトップページを開いたとき、トップページは URL クエリの条件を入力欄・フィルターに復元し、その条件で絞り込んだ結果を表示しなければならない。
- 事前条件: なし
- 事後条件: 表示結果は同じ条件を手動入力した場合と同一である
- 不変条件: なし
- 検証: E2E テスト

### TOP-013 不正なクエリ値

- パターン: 望ましくない振る舞い
- EARS: もし URL クエリの `type` が定義外の値、または `tags` に索引に存在しないタグを含むならば、トップページは当該値を無視し、エラーを表示せずに残りの条件で絞り込まなければならない。
- 事前条件: なし
- 事後条件: 無視した値は URL からも除去される
- 不変条件: なし
- 検証: E2E テスト

### TOP-014 スクリプト無効時

- パターン: 状態駆動
- EARS: クライアント側スクリプトが無効な間、トップページは全アイテムのカードとリンクを表示し、検索欄とフィルターを表示してはならない。
- 事前条件: なし
- 事後条件: 利用者はスクリプト無しでも全アイテムの詳細ページへ遷移できる
- 不変条件: なし
- 検証: E2E テスト（JavaScript 無効）

## 4. モジュール契約

### `filterItems`

| 項目 | 内容 |
|---|---|
| シグネチャ | `filterItems(entries: CatalogIndexEntry[], query: { q: string; type: ItemType \| "all"; tags: string[] }): CatalogIndexEntry[]` |
| 事前条件 | `entries` は `buildCatalogIndex` の出力である。`query.tags` の各要素は正規化済みである |
| 事後条件 | 戻り値は `entries` の部分列（相対順序を保持）であり、各要素は「2. 検索・絞り込み条件の定義」に一致し、`entries` 中の一致する要素をすべて含む。条件がすべて既定値なら `entries` と同じ要素列を返す |
| 不変条件 | 入力を変更しない。副作用なし |
| 違反時 | `query.type` が定義外の場合はエラーを送出する（URL 由来の不正値は呼び出し前に TOP-013 で除去する） |

### `parseQuery` / `serializeQuery`

| 項目 | 内容 |
|---|---|
| シグネチャ | `parseQuery(search: string, knownTags: Set<string>): Query` / `serializeQuery(query: Query): string` |
| 事前条件 | `knownTags` は索引に存在する正規化済みタグの集合である |
| 事後条件 | `parseQuery` は TOP-013 に従い不正値を除去した `Query` を返す。任意の有効な `Query` について `parseQuery(serializeQuery(q), knownTags)` は `q` と等価である（往復性） |
| 不変条件 | 副作用なし |
| 違反時 | 例外を送出しない（不正値は除去する） |
