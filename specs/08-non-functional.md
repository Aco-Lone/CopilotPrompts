# 08. 非機能要件

## 1. 性能・規模

### NFR-001 想定規模

- パターン: ユビキタス
- EARS: サイトは、アイテム数 500 件・タグ種類数 200 件までを設計変更なしで扱えなければならない。
- 事前条件: なし
- 事後条件: 500 件のフィクスチャで NFR-002・NFR-003 を満たす
- 不変条件: なし
- 検証: 性能テスト（生成フィクスチャ）

### NFR-002 絞り込みの応答時間

- パターン: イベント駆動
- EARS: 利用者が検索・絞り込み条件を変更したとき、トップページは 100 ミリ秒以内に表示を更新しなければならない。
- 事前条件: アイテム数 ≦ 500。計測環境はデスクトップ版 Chrome、CPU スロットリング 4 倍
- 事後条件: 入力イベントから DOM 更新完了までの時間 ≦ 100 ms
- 不変条件: なし
- 検証: 性能テスト（Playwright + Performance API）

### NFR-003 ページの軽量性

- パターン: ユビキタス
- EARS: 各ページのクライアント側 JavaScript は、gzip 圧縮後の合計で 50 KB 以下でなければならない。
- 事前条件: なし
- 事後条件: Lighthouse（モバイル）の Performance スコアが 90 以上
- 不変条件: 詳細ページはコピーボタン以外のクライアント側スクリプトを必要としない
- 検証: ビルド成果物のサイズ計測、Lighthouse CI

## 2. アクセシビリティ

### NFR-004 準拠基準

- パターン: ユビキタス
- EARS: サイトは、WCAG 2.2 レベル AA に準拠しなければならない。
- 事前条件: なし
- 事後条件: axe-core による自動検査で違反 0 件
- 不変条件: なし
- 検証: E2E テスト（`@axe-core/playwright`）、手動のキーボード操作確認

### NFR-005 キーボード操作

- パターン: ユビキタス
- EARS: サイトは、検索欄・種別フィルター・タグフィルター・アイテムカード・コピーボタンのすべてをキーボードのみで操作可能にし、フォーカス位置を視覚的に示さなければならない。
- 事前条件: なし
- 事後条件: Tab / Shift+Tab / Enter / Space で全操作が完了できる
- 不変条件: フォーカス順序は視覚的な配置順と一致する
- 検証: E2E テスト

### NFR-006 状態変化の通知

- パターン: イベント駆動
- EARS: 件数表示（TOP-009）・一致なしメッセージ（TOP-010）・コピー結果（DTL-006 / DTL-007）が更新されたとき、サイトはそれらを `aria-live="polite"` 領域でスクリーンリーダーに通知しなければならない。
- 事前条件: なし
- 事後条件: スクリーンリーダー利用者が結果の変化を知覚できる
- 不変条件: なし
- 検証: E2E テスト（属性の検査）

### NFR-007 フィルターの状態表現

- パターン: ユビキタス
- EARS: タグフィルターの各タグは `aria-pressed` で選択状態を、種別フィルターはラジオグループとして選択状態を表現しなければならない。検索欄は可視ラベルを持たなければならない。
- 事前条件: なし
- 事後条件: 支援技術が各フィルターの選択状態を読み上げられる
- 不変条件: なし
- 検証: E2E テスト

## 3. セキュリティ

### NFR-008 README 由来 HTML のサニタイズ

- パターン: ユビキタス
- EARS: ビルドは、README 本文から生成した HTML を許可リスト方式（GitHub 相当のスキーマ）でサニタイズしなければならない。
- 事前条件: なし
- 事後条件: 出力 HTML に `<script>`・`<iframe>`・`<object>`・`<embed>`・`<style>`・`on*` 属性・`javascript:` / `data:` スキームのリンクが含まれない
- 不変条件: Markdown で表現できる通常の要素（見出し・表・リスト・コード・画像・リンク）は保持する
- 検証: 単体テスト（悪性入力のフィクスチャ）

### NFR-009 フロントマター値のエスケープ

- パターン: ユビキタス
- EARS: サイトは、フロントマター由来の値（`title`・`summary`・`tags` 等）を HTML・属性・埋め込み JSON に出力する際、それぞれの文脈に応じてエスケープしなければならない。
- 事前条件: なし
- 事後条件: `title` に `<script>` や `</script>` を含むアイテムでもスクリプトが実行されない
- 不変条件: 表示上の文字列は README 上の値と同一である
- 検証: 単体テスト、E2E テスト

### NFR-010 外部通信の禁止

- パターン: ユビキタス
- EARS: サイトは、アクセス解析・広告・外部フォント・外部 CDN のスクリプトを読み込んではならず、Cookie を設定してはならない。
- 事前条件: なし
- 事後条件: 実行時の外部通信は、README 本文中の画像（`raw.githubusercontent.com` 等）と利用者がクリックしたリンクのみである
- 不変条件: なし
- 検証: E2E テスト（ネットワーク要求の監視）

### NFR-011 外部リンクの扱い

- パターン: ユビキタス
- EARS: サイトは、別オリジンへのリンクに `rel="noopener noreferrer"` を付与しなければならない。
- 事前条件: なし
- 事後条件: 遷移先ページから `window.opener` を参照できない
- 不変条件: なし
- 検証: 単体テスト

- 検証: ビルド検証

## 5. 保守性

- パターン: ユビキタス

- 事前条件: なし

- 不変条件: なし

### NFR-016 テストの網羅

- EARS: `site/src/lib/` 配下のモジュール（本仕様でモジュール契約を定めたもの）は、単体テストで行カバレッジ 90% 以上でなければならない。
- 事前条件: なし

### NFR-017 依存の固定

- パターン: ユビキタス
- EARS: サイトは、`site/package-lock.json` をリポジトリに含め、CI では `npm ci` で依存を導入しなければならない。
- 事前条件: なし

- 不変条件: なし
- 検証: ワークフロー定義のレビュー
