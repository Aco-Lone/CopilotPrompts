# 04. 詳細ページ（README 表示・ダウンロードコマンド）

## 1. 画面構成

| 領域 | 内容 |
|---|---|
| パンくず | 「トップ」へのリンク > アイテムの `title` |
| 見出し | `title`、種別バッジ |
| 概要 | `summary` |
| メタ情報 | タグ（トップページの絞り込みへのリンク）、`version`・`author`・`updated`（指定時のみ） |
| ダウンロード | ダウンロードコマンド、コピーボタン、同梱ファイル一覧 |
| ソース | GitHub 上の配布フォルダへのリンク |
| 本文 | README 本文の HTML |

- URL: `<base>/items/<slug>/`（例: `https://aco-lone.github.io/CopilotPrompts/items/tdd-orchestration/`）
- ダウンロード領域は本文より前（画面上部）に配置する。

## 2. 要件

### DTL-001 詳細ページの表示

- パターン: ユビキタス
- EARS: 詳細ページは、`<base>/items/<slug>/` で当該アイテムの見出し・概要・メタ情報・ダウンロード領域・ソースリンク・本文を表示しなければならない。
- 事前条件: slug のアイテムがビルド時に存在した（BLD-008）
- 事後条件: 表示される `title`・`summary`・`type`・`tags` はアイテム README のフロントマターと一致する
- 不変条件: なし
- 検証: E2E テスト

### DTL-002 任意メタ情報の表示

- パターン: オプション
- EARS: フロントマターに `version`・`author`・`updated` のいずれかが指定されている場合、詳細ページは指定された項目のみをメタ情報に表示しなければならない。
- 事前条件: なし
- 事後条件: 未指定の項目のラベルは表示されない。`updated` は `YYYY-MM-DD` 形式で表示する
- 不変条件: なし
- 検証: E2E テスト

### DTL-003 本文の表示

- パターン: ユビキタス
- EARS: 詳細ページは、アイテム README の本文を BLD-009・BLD-011 に従って変換した HTML として表示しなければならない。
- 事前条件: 本文が空でない
- 事後条件: フロントマターの YAML 文字列は表示されない
- 不変条件: なし
- 検証: E2E テスト

### DTL-004 本文が空の場合

- パターン: 状態駆動
- EARS: 本文が空または空白のみである間、詳細ページは本文領域に「説明はありません」と表示しなければならない。
- 事前条件: なし
- 事後条件: ダウンロード領域は通常どおり表示される
- 不変条件: なし
- 検証: E2E テスト

### DTL-005 ダウンロードコマンドの表示

- パターン: ユビキタス
- EARS: 詳細ページは、`buildGigetCommand` が生成したダウンロードコマンドを等幅フォントのコードブロックで表示しなければならない。
- 事前条件: BLD-010 のサイト設定が取得できる
- 事後条件: 表示文字列は [05-download-command.md](./05-download-command.md) の CMD-001 の形式と一致する
- 不変条件: コマンドは折り返さずに 1 行で表示し、ブロック幅を超える部分はブロック内で横スクロールさせる（NFR-013）
- 検証: E2E テスト

### DTL-006 コマンドのコピー

- パターン: イベント駆動
- EARS: 利用者がコピーボタンを押したとき、詳細ページはダウンロードコマンドをクリップボードに書き込み、ボタン付近に「コピーしました」を 2 秒間表示しなければならない。
- 事前条件: ブラウザが Clipboard API（`navigator.clipboard.writeText`）を利用できる
- 事後条件: クリップボードの内容 = 表示中のコマンド文字列（前後の空白・改行・プロンプト記号 `$` を含まない）
- 不変条件: 表示中のコマンド文字列を変更しない
- 検証: E2E テスト

### DTL-007 コピー失敗時

- パターン: 望ましくない振る舞い
- EARS: もしクリップボードへの書き込みが失敗した、または Clipboard API が利用できないならば、詳細ページは「コピーできませんでした。コマンドを選択してコピーしてください」と表示し、コマンド文字列全体を選択状態にしなければならない。
- 事前条件: 利用者がコピーボタンを押した
- 事後条件: 利用者はキーボード操作（Ctrl+C 等）でコマンドをコピーできる
- 不変条件: なし
- 検証: E2E テスト（Clipboard API をモック）

### DTL-008 同梱ファイル一覧

- パターン: ユビキタス
- EARS: 詳細ページは、ダウンロードで取得される配布フォルダ内の全ファイルの相対パスを、パスの昇順で一覧表示しなければならない。
- 事前条件: ビルド時に配布フォルダを走査できる
- 事後条件: 一覧のファイル数 = 配布フォルダ内のファイル数（`README.md` を含む）。各パスは GitHub 上の該当ファイルへのリンクである
- 不変条件: なし
- 検証: ビルド検証、E2E テスト

### DTL-009 ソースへのリンク

- パターン: ユビキタス
- EARS: 詳細ページは、`https://github.com/<owner>/<repo>/tree/<ref>/catalog/<slug>` へのリンクを表示しなければならない。
- 事前条件: BLD-010 のサイト設定が取得できる
- 事後条件: リンク先は新しいタブで開く（`target="_blank"` と `rel="noopener noreferrer"`）
- 不変条件: なし
- 検証: E2E テスト

### DTL-010 タグからトップページへの遷移

- パターン: イベント駆動
- EARS: 利用者が詳細ページのタグをクリックしたとき、詳細ページは `<base>/?tags=<正規化済みタグ>` へ遷移しなければならない。
- 事前条件: なし
- 事後条件: トップページは TOP-012 によりそのタグで絞り込んだ状態で表示される
- 不変条件: なし
- 検証: E2E テスト

### DTL-011 存在しない slug

- パターン: 望ましくない振る舞い
- EARS: もし存在しない slug の URL にアクセスされたならば、サイトは「アイテムが見つかりません」というメッセージとトップページへのリンクを持つ 404 ページを表示しなければならない。
- 事前条件: なし
- 事後条件: GitHub Pages は HTTP ステータス 404 を返す（`404.html` を配置）
- 不変条件: なし
- 検証: E2E テスト

### DTL-012 ページのメタデータ

- パターン: ユビキタス
- EARS: 詳細ページは、`<title>` を「`<title>` | `<サイト名>`」、`<meta name="description">` を `summary` としなければならない。
- 事前条件: なし
- 事後条件: ブラウザのタブと検索結果・共有時にアイテム名と概要が表示される
- 不変条件: なし
- 検証: ビルド検証

## 3. モジュール契約

### `listItemFiles`

| 項目 | 内容 |
|---|---|
| シグネチャ | `listItemFiles(itemDir: string): string[]` |
| 事前条件 | `itemDir` は `catalog/<slug>` を指す存在するディレクトリである |
| 事後条件 | 戻り値は `itemDir` 配下の全ファイル（サブフォルダを再帰的に含む）の、`/` 区切りの相対パスを昇順に並べた配列である。ディレクトリ自体は含まない |
| 不変条件 | ファイルシステムを変更しない |
| 違反時 | ディレクトリが存在しない場合はビルドを失敗させるエラーを送出する |

### `CopyButton`（クライアントコンポーネント）

| 項目 | 内容 |
|---|---|
| シグネチャ | `<CopyButton text={string} />` |
| 事前条件 | `text` は 1 文字以上で改行を含まない |
| 事後条件 | 押下時に DTL-006 または DTL-007 のいずれか一方の状態になる |
| 不変条件 | `text` を変更しない。押下以外の契機でクリップボードに触れない |
| 違反時 | ビルド時に `text` が空ならエラーを送出する |
