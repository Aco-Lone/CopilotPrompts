# 05. ダウンロードコマンド（giget）

## 1. コマンド形式

```text
npx giget@latest gh:<owner>/<repo>/catalog/<slug>#<ref> ./<slug>
```

| 部分 | 値 | 出典 |
|---|---|---|
| `npx giget@latest` | 固定 | 本仕様 |
| `gh:` | 固定（GitHub プロバイダー） | giget の書式 |
| `<owner>` / `<repo>` / `<ref>` | 既定は `Aco-Lone` / `CopilotPrompts` / `main` | `site/site.config.ts`（BLD-010） |
| `catalog/<slug>` | 配布フォルダのパス | アイテムの slug |
| `./<slug>` | 出力先ディレクトリ | アイテムの slug |

### 例

```text
npx giget@latest gh:Aco-Lone/CopilotPrompts/catalog/tdd-orchestration#main ./tdd-orchestration
```

実行すると、カレントディレクトリに `tdd-orchestration/` が作成され、配布フォルダ内の全ファイル（`README.md` を含む）が展開される。
取得したファイルを `.github/agents/` 等へ配置するのは利用者の作業とする。

## 2. 要件

### CMD-001 コマンドの生成

- パターン: ユビキタス
- EARS: サイトは、各アイテムのダウンロードコマンドを「1. コマンド形式」に従い `buildGigetCommand` で生成しなければならない。
- 事前条件: slug が CNT-002 を、サイト設定が CMD-003 を満たす
- 事後条件: コマンドは 1 行で、区切りは半角空白 1 つである
- 不変条件: 同じ slug とサイト設定からは常に同じ文字列を生成する
- 検証: 単体テスト（`buildGigetCommand`）

### CMD-002 出力先の固定

- パターン: ユビキタス
- EARS: ダウンロードコマンドの出力先は、常に `./<slug>` でなければならない。
- 事前条件: なし
- 事後条件: アイテムの種別にかかわらず、利用者のカレントディレクトリ直下の `<slug>` フォルダに展開される
- 不変条件: フロントマターや種別によって出力先を変えない
- 検証: 単体テスト

### CMD-003 シェル安全な文字のみの使用

- パターン: ユビキタス
- EARS: ダウンロードコマンドは、bash・zsh・PowerShell・cmd.exe のいずれでもクォート無しで同じ引数として解釈される文字のみで構成されなければならない。
- 事前条件: なし
- 事後条件: `owner`・`repo` は `^[A-Za-z0-9_.-]+$`、`ref` は `^[A-Za-z0-9._/-]+$`、slug は CNT-002 に一致する
- 不変条件: コマンドに空白・引用符・`$`・`;`・`&`・`|`・`` ` `` を含む値を埋め込まない
- 検証: 単体テスト
- 備考: `#` はトークン途中に現れるため、bash・PowerShell でコメントとして解釈されない

### CMD-004 不正なサイト設定

- パターン: 望ましくない振る舞い
- EARS: もしサイト設定の `owner`・`repo`・`ref` が CMD-003 の正規表現に一致しないならば、ビルドは当該設定キーを示して失敗しなければならない。
- 事前条件: なし
- 事後条件: 不正なコマンドを含むページは公開されない
- 不変条件: なし
- 検証: 単体テスト

### CMD-005 上書きしない既定動作

- パターン: ユビキタス
- EARS: ダウンロードコマンドは `--force` などの上書きオプションを含んではならない。
- 事前条件: なし
- 事後条件: 出力先が既に存在する場合、giget は既存ファイルを上書きせずに失敗する
- 不変条件: なし
- 検証: 単体テスト

### CMD-006 利用上の注意の表示

- パターン: ユビキタス
- EARS: 詳細ページは、ダウンロードコマンドの近くに次の注意事項を表示しなければならない。
  - Node.js（`npx`）が必要であること
  - カレントディレクトリに `<slug>` フォルダが作成されること
  - 同名フォルダが既に存在する場合は失敗すること、および上書きしたい場合は `--force` を付けられること
- 事前条件: なし
- 事後条件: 利用者はコマンド実行前に結果と前提を把握できる
- 不変条件: コピーされるコマンド文字列には注意事項を含めない
- 検証: E2E テスト

### CMD-007 取得内容と配布フォルダの一致

- パターン: ユビキタス
- EARS: ダウンロードコマンドで取得されるファイル集合は、`<ref>` 時点の `catalog/<slug>/` 配下の全ファイルと一致しなければならない。
- 事前条件: `<ref>` に当該配布フォルダが存在する。リポジトリが公開されている
- 事後条件: 取得ファイル集合 = DTL-008 の同梱ファイル一覧（同一コミット時点）
- 不変条件: 配布フォルダ外のファイルは取得されない
- 検証: 手動確認（リリース時に代表アイテムで `npx giget` を実行）

## 3. モジュール契約

### `buildGigetCommand`

| 項目 | 内容 |
|---|---|
| シグネチャ | `buildGigetCommand(slug: string, config: { owner: string; repo: string; ref: string }): string` |
| 事前条件 | `validateSlug(slug) === true`。`config` の各値が CMD-003 の正規表現に一致する |
| 事後条件 | 戻り値 = `` `npx giget@latest gh:${owner}/${repo}/catalog/${slug}#${ref} ./${slug}` ``。改行・タブ・連続空白を含まない |
| 不変条件 | 副作用なし。引数を変更しない |
| 違反時 | 事前条件違反の場合、違反した引数名を含むエラーを送出する（ビルド失敗となる） |
