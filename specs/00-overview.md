# 00. 概要・記法規約

## 1. 目的

GitHub Copilot 用のカスタムエージェント・Skills・プロンプトを **配布単位（アイテム）** ごとにフォルダへまとめ、
GitHub Pages 上のカタログサイトで以下を可能にする。

- トップページでアイテムの概要を一覧・検索・絞り込みできる
- 概要をクリックすると詳細ページへ遷移し、README の内容とダウンロードコマンドを確認できる
- ダウンロードコマンド（`npx giget`）をコピーして、利用者のローカルへアイテムを取得できる

## 2. スコープ

| 区分 | 内容 |
|---|---|
| スコープ内 | `catalog/` 配下の配布フォルダ規約、README フロントマター規約、Astro による静的サイト生成、トップページ、詳細ページ、giget コマンド生成、GitHub Actions による Pages デプロイ、既存ファイルの移行 |
| スコープ外 | 利用者認証、アイテムの投稿 UI（投稿は Git の PR で行う）、ダウンロード数等の統計、サーバーサイド処理、多言語切替、README 本文の全文検索 |

## 3. 用語集

| 用語 | 定義 |
|---|---|
| アイテム | 配布単位。`catalog/<slug>/` フォルダ 1 つに対応する |
| slug | アイテムの識別子。配布フォルダ名と同一（規則は [01-content-model.md](./01-content-model.md)） |
| 種別（type） | アイテムの分類。`agent` / `skill` / `prompt` / `bundle` のいずれか |
| bundle | 複数種別のファイル、または複数エージェントを組み合わせたアイテム |
| アイテム README | `catalog/<slug>/README.md`。フロントマターと本文からなる |
| フロントマター | アイテム README 先頭の YAML ブロック（`---` で囲まれた部分） |
| 本文 | アイテム README のフロントマターを除いた Markdown 部分 |
| カタログ索引 | ビルド時に全アイテムのフロントマターから生成する、検索・一覧用のデータ |
| ダウンロードコマンド | アイテムを取得するための `npx giget` コマンド文字列 |
| サイト | 本仕様で定義する GitHub Pages 上の静的 Web サイト |
| ビルド | Astro によりサイトを静的ファイルとして生成する処理 |
| 利用者 | サイトを閲覧し、アイテムを取得する人 |
| 作者 | アイテムを `catalog/` に追加・更新する人 |

## 4. アクター

| アクター | 主な操作 |
|---|---|
| 利用者 | 一覧閲覧、検索、絞り込み、詳細閲覧、コマンドのコピー |
| 作者 | 配布フォルダと README の追加・更新、PR 作成 |
| GitHub Actions | ビルド・検証・デプロイの自動実行 |

## 5. 前提となる構成

| 項目 | 値 |
|---|---|
| リポジトリ | `Aco-Lone/CopilotPrompts` |
| 既定ブランチ | `main` |
| 配布フォルダの親 | `catalog/` |
| 静的サイト生成 | Astro（Content Collections） |
| ホスティング | GitHub Pages（GitHub Actions によるデプロイ） |
| ダウンロードツール | `giget`（unjs）を `npx` で実行 |

リポジトリ名・ブランチ名はサイト設定（[02-build.md](./02-build.md) の `BLD-010`）で一元管理する。

## 6. 記法規約

### 6.1 要件 ID

`<接頭辞>-<3 桁連番>` 形式とする（例: `TOP-001`）。接頭辞はファイルごとに固定する。

| 接頭辞 | ファイル |
|---|---|
| `OVR` | 00-overview.md |
| `CNT` | 01-content-model.md |
| `BLD` | 02-build.md |
| `TOP` | 03-top-page.md |
| `DTL` | 04-detail-page.md |
| `CMD` | 05-download-command.md |
| `DEP` | 06-deployment.md |
| `MIG` | 07-migration.md |
| `NFR` | 08-non-functional.md |

一度割り当てた ID は再利用しない。削除した要件は「廃止」と明記して ID を残す。

### 6.2 EARS パターン（日本語テンプレート）

| パターン | テンプレート |
|---|---|
| ユビキタス | 〈システム〉は〈応答〉しなければならない。 |
| イベント駆動 | 〈トリガー〉とき、〈システム〉は〈応答〉しなければならない。 |
| 状態駆動 | 〈状態〉の間、〈システム〉は〈応答〉しなければならない。 |
| 望ましくない振る舞い | もし〈望ましくない事象〉ならば、〈システム〉は〈応答〉しなければならない。 |
| オプション | 〈機能・設定〉が有効な場合、〈システム〉は〈応答〉しなければならない。 |
| 複合 | 上記の組み合わせ（例: 〈状態〉の間、〈トリガー〉とき、…） |

### 6.3 要件ブロックの書式

各要件は以下の書式で記述する。EARS 文で「何をするか」を、DbC 項目で「成立条件と保証」を表す。

```markdown
### TOP-001 フリーワード検索

- パターン: イベント駆動
- EARS: 利用者が検索欄に文字列を入力したとき、トップページは〜を表示しなければならない。
- 事前条件: 要件が適用されるために成立していなければならない条件
- 事後条件: 応答後に必ず成立する条件
- 不変条件: 応答の前後で変化してはならない条件（該当なしの場合は「なし」）
- 検証: 確認手段（単体テスト / E2E テスト / ビルド検証 / レビュー）
```

- 事前条件が満たされない場合の振る舞いは、別の「望ましくない振る舞い」要件として定義する。
- 「〜しなければならない」は必須、「〜すべきである」は推奨を表す。

### 6.4 モジュール契約（DbC）の書式

実装上の関数・コンポーネントの契約は、以下の表で記述する。

| 項目 | 内容 |
|---|---|
| シグネチャ | 名前・引数・戻り値の型 |
| 事前条件 | 呼び出し側が保証すべき条件 |
| 事後条件 | 関数が戻り値・副作用について保証する条件 |
| 不変条件 | 呼び出し前後で保たれる条件 |
| 違反時 | 事前条件違反時の挙動（例外、ビルド失敗など） |

## 7. 全体要件

### OVR-001 静的サイトとしての提供

- パターン: ユビキタス
- EARS: サイトは、サーバーサイド処理を用いず、ビルド時に生成した静的ファイルのみで全機能を提供しなければならない。
- 事前条件: なし
- 事後条件: 公開されるファイルは HTML / CSS / JavaScript / JSON / 画像などの静的ファイルのみである
- 不変条件: 実行時に外部 API を呼び出さない
- 検証: ビルド成果物のレビュー

### OVR-002 単一の情報源

- パターン: ユビキタス
- EARS: サイトは、アイテムの表示内容をすべて `catalog/<slug>/README.md` から導出しなければならない。
- 事前条件: なし
- 事後条件: アイテムの title / summary / tags / type / 本文は README 以外に定義されない
- 不変条件: サイト側のソースコードにアイテム固有の情報をハードコードしない
- 検証: コードレビュー

### OVR-003 トレーサビリティ

- パターン: ユビキタス
- EARS: 実装のテストは、検証対象の要件 ID をテスト名またはコメントに含めるべきである。
- 事前条件: なし
- 事後条件: 要件 ID からテストを検索できる
- 不変条件: なし
- 検証: レビュー
